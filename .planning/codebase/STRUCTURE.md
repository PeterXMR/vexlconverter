## Directory Purposes

**backend/:**
- Purpose: Flask REST API, price fetching, database operations
- Contains: Python application code, ORM models, scheduled jobs
- Key files: `app.py` (endpoints), `models.py` (data schema), `scheduler.py` (background jobs)

**frontend/src/:**
- Purpose: React application source code
- Contains: Components, styles, entry point, tests
- Key files: `Converter.js` (main UI), `App.js` (root), `index.js` (bootstrap)

**frontend/src/components/:**
- Purpose: Reusable React components
- Contains: Converter, CurrencySelector, PriceCard with their styles
- Key files: `Converter.js` (large, contains most logic), `PriceCard.js`, `CurrencySelector.js`

**database/:**
- Purpose: Database schema initialization
- Contains: SQL scripts executed on PostgreSQL startup
- Key files: `init.sql` (creates btc_prices and conversion_history tables)

**.planning/codebase/:**
- Purpose: Codebase analysis and documentation
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Generated by: `/gsd:map-codebase` command

**.github/workflows/:**
- Purpose: CI/CD automation
- Contains: GitHub Actions workflow definitions
- Key files: docker-publish.yml (Docker image publishing)

## Naming Conventions

**Files:**

- **Component files:** PascalCase (e.g., `Converter.js`, `PriceCard.js`)
- **Style files:** Match component name with `.css` extension (e.g., `Converter.css`)
- **Python files:** snake_case (e.g., `app.py`, `scheduler.py`, `models.py`)
- **Test files:** Match source name with `.test.js` suffix (e.g., `App.test.js`)

**Directories:**

- **React components:** `components/` (plural)
- **Python modules:** Top-level in `backend/`, flat structure (no nested packages)
- **Static assets:** `public/` for frontend, `/static/` route for backend

**Functions:**

**JavaScript:**
- Functional components: PascalCase (e.g., `Converter()`, `App()`)
- Regular functions: camelCase (e.g., `fetchLatestPrices()`, `handleBtcChange()`)
- Constants: UPPER_SNAKE_CASE (e.g., `API_URL`, `SATS_PER_BTC`)
- Event handlers: `handle{Action}` pattern (e.g., `handleBtcChange`, `handleAdd`)

**Python:**
- Functions: snake_case (e.g., `fetch_and_store_prices()`, `start_scheduler()`)
- Classes: PascalCase (e.g., `BTCPrice`)
- Constants: UPPER_SNAKE_CASE (e.g., `COINGECKO_API`, `SATS_PER_BTC`)

**Variables:**

**Frontend:**
- State: camelCase (e.g., `btcAmount`, `lastUpdate`, `loading`)
- Props: camelCase (e.g., `onAddCurrency`, `isDefault`)
- Constants: UPPER_SNAKE_CASE with `const` (e.g., `API_URL`, `SATS_PER_BTC`)

**Backend:**
- Database columns: snake_case (e.g., `btc_usd`, `created_at`)
- Function parameters: snake_case (e.g., `btc_amount`, `retry_delay`)

## Where to Add New Code

**New Feature (e.g., add price history view):**
- Primary code: `frontend/src/components/` (new component file)
- API endpoint: `backend/app.py` (new route function)
- Tests: `frontend/src/components/{Name}.test.js`

**New Component/Module:**
- React component: `frontend/src/components/{ComponentName}.js` + `{ComponentName}.css`
- Python module: `backend/{module_name}.py` (if significant) or inline in `app.py`
- Add imports: Reference from parent components or `app.py`

**Utilities:**
- Frontend helpers: Create in `frontend/src/utils/` (directory doesn't exist yet, follow pattern)
- Backend helpers: Add functions to `backend/app.py` or new `backend/{helper_name}.py`
- Shared constants: Frontend in component file or top of `Converter.js`, backend in `models.py`

**Tests:**
- Unit tests: `frontend/src/__tests__/` or co-locate with `.test.js` suffix
- Backend tests: `backend/test_*.py` files (follow existing `test_setup.py` pattern)

## Special Directories

**frontend/node_modules/:**
- Purpose: NPM installed dependencies (React, axios, testing-library)
- Generated: Yes, by `npm install`
- Committed: No (in .gitignore)
- Size: ~500MB typically

**frontend/build/:**
- Purpose: Production build output from `npm run build`
- Generated: Yes, by build script
- Committed: No (in .gitignore)
- Note: Frontend Dockerfile copies from this directory

**backend/.venv/ or venv/:**
- Purpose: Python virtual environment (if used locally)
- Generated: Yes, by `python -m venv`
- Committed: No (in .gitignore)
- Note: Backend Dockerfile uses Alpine without venv

**postgres_data/ (Docker volume):**
- Purpose: PostgreSQL database persistence
- Generated: Yes, by Docker daemon
- Committed: No, persists on host machine
- Note: Destroyed when running `docker-compose down -v`
